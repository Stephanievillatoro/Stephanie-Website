ISDS Capstone Case Study

Enterprise Supply Chain Analytics & Relational Database Optimization

A comprehensive business systems engineering initiative replacing disconnected legacy spreadsheets with a normalized 3NF MySQL relational database and automated Power BI intelligence dashboards.

Role Lead Systems & Data Analyst
Domain Supply Chain & Inventory Management
Technologies MySQL, Power BI, Advanced Excel, Git
Timeline Spring Semester Practicum

1. The Business Challenge

Regional distribution operations frequently suffer when critical inventory and fulfillment logs are scattered across isolated desktop spreadsheets. In our client scenario, a distribution provider managing over 1,200 SKUs across four fulfillment centers struggled with recurring challenges:

  • Severe Data Redundancy: Discrepancies between warehouse inventory sheets and purchase orders created duplicate entries and stockouts.
  • Latency in Reporting: Compiling monthly vendor lead-time summaries took over 30 hours of manual copy-pasting in Excel.
  • Lack of Predictive Visibility: Decision-makers lacked real-time visibility into high-velocity inventory turnover, resulting in an estimated 18% excess holding cost.

2. Systems Architecture & Database Design

To establish a single source of truth, I designed a normalized relational database schema adhering to Third Normal Form (3NF). This eliminated transitive dependencies, maintained strict referential integrity with foreign key constraints, and established indexing on high-frequency query paths.

Relational Entity Relationships (ERD Highlights)

+------------------+ +-------------------+ +-------------------+ | SUPPLIERS | 1 * | PURCHASE_ORDERS | 1 * | PO_LINE_ITEMS | |------------------+<--------+-------------------+<--------+-------------------| | supplier_id (PK) | | po_id (PK) | | item_id (PK) | | company_name | | supplier_id (FK) | | po_id (FK) | | lead_time_days | | order_date | | product_id (FK) | +------------------+ | status_code | | quantity_ordered | +-------------------+ | unit_cost | +-------------------+ | * +------------------+ +-------------------+ | 1 | WAREHOUSES | 1 * | INVENTORY | * 1 v |------------------+<--------+-------------------+<---------+-------------------+ | warehouse_id(PK) | | inventory_id (PK) | | PRODUCTS | | facility_code | | warehouse_id (FK) | |-------------------| | location_state | | product_id (FK) | | product_id (PK) | +------------------+ | stock_on_hand | | sku_code | | safety_stock_lvl | | category_id (FK) | +-------------------+ | reorder_point | +-------------------+

Normalized 3NF relational data model supporting relational constraints across suppliers, purchase orders, products, and multi-facility inventory tracking.

Sample Analytical SQL Query

Below is an excerpt of the analytical SQL view developed to compute warehouse stockout risk and supplier fulfillment adherence in real time:

-- Identify products currently operating below safety stock threshold SELECT w.facility_code, p.sku_code, p.product_name, i.stock_on_hand, i.safety_stock_lvl, (i.safety_stock_lvl - i.stock_on_hand) AS units_needed, s.company_name AS primary_supplier, s.lead_time_days FROM INVENTORY i JOIN PRODUCTS p ON i.product_id = p.product_id JOIN WAREHOUSES w ON i.warehouse_id = w.warehouse_id JOIN SUPPLIERS s ON p.primary_supplier_id = s.supplier_id WHERE i.stock_on_hand < i.safety_stock_lvl ORDER BY (i.safety_stock_lvl - i.stock_on_hand) DESC;

3. Power BI Executive Dashboard

Connecting the MySQL database directly to Microsoft Power BI, I engineered dynamic executive and operational reports utilizing DAX (Data Analysis Expressions). Key metrics and visual components included:

Operational Inventory View

Heatmap of stock levels across regional warehouses with automated conditional color triggers for items nearing minimum reorder thresholds.

Vendor Scorecard

Calculated On-Time In-Full (OTIF) fulfillment rates per vendor, giving procurement teams leverage during contract renegotiations.

5. Managerial & GenAI Takeaways

"In the era of Generative AI and automated systems, managerial judgment is the irreplaceable differentiator. The AI can generate code or analyze data, but the manager must define the system goals, validate data fidelity, and decide what performance is acceptable."

Executing this project reinforced the essential skills of an ISDS manager: writing precise system specifications, using AI pair programming to accelerate schema development, and critically evaluating technical deliverables against strategic business objectives.
